# UX 흐름과 화면 구성

> 관련: [PRD](PRD.md) · [아키텍처](architecture.md) · [노션 레이아웃](templates/notion-layout.md)

## 1. UX 원칙

1. **기다리게 하지 말고 알려주기**: 처리는 백그라운드에서 합니다. 사용자는 알림을 받고 검토만 합니다.
2. **검토는 5분 안에**: 확인이 필요한 곳(`미정`, 이전 액션 판단, 화자 이름)만 눈에 띄게 하고, 근거 구간으로 바로 이동합니다.
3. **설정은 한 번, 탐지는 자동**: 녹음 도구와 폴더는 앱이 먼저 찾아서 제안합니다.
4. **어디로 무엇이 가는지 항상 보이게**: 로컬/클라우드 배지와 예상 비용을 보여줍니다.
5. **실패해도 막히지 않게**: 모든 오류에 한 줄 설명과 복구 버튼을 줍니다. 앞 단계 결과는 보존합니다.

## 2. 화면 지도

```
앱 창
├─ 사이드바
│   ├─ 🏠 홈 (받은 녹음함 · 처리 중 · 검토 대기)
│   ├─ 📚 히스토리 (검색·필터)
│   ├─ 🧩 템플릿
│   └─ ⚙️ 설정 (AI 제공자 · 음성인식 · 노션 · 저장 · 녹음 소스 · 프로젝트 · 사람 · 용어집 · 개인정보)
├─ 회의 상세 (홈·히스토리·알림에서 진입)
├─ 설정 마법사 (첫 실행 · 설정에서 다시 실행)
└─ 트레이/메뉴바 메뉴 (P1)
```


- **오른쪽 편집**:
  - 유형 섹션은 표·폼으로 편집합니다. 행 추가·삭제·드래그, 담당자는 사람 디렉토리에서 자동완성합니다.
  - 자유 섹션은 CodeMirror 마크다운으로 편집합니다.
- **근거 이동**: 근거 구간(↗)을 클릭하면 왼쪽 전사본이 그 구간으로 스크롤하고 재생 위치를 옮깁니다(P1).
- **다시 생성 ▾**:
  - 전체 또는 섹션만 다시 생성
  - 다른 제공자·모델로 다시 생성
  - 템플릿을 바꿔서 다시 생성
- **발행 후**: 버튼이 [🔄 노션 업데이트]로 바뀌고 노션 링크가 나타납니다. 노션에서 수정된 내용이 있으면 충돌 대화상자를 띄웁니다.

## 10. 주요 사용자 시나리오

### 시나리오 A — Zoom 회의 (자동 흐름)

1. 김대리가 Zoom 회의를 로컬 녹화합니다. 회의가 끝나면 Zoom이 `audio_only.m4a`를 만듭니다.
2. 앱이 파일을 감지하고 알림을 띄웁니다. 폴더명에서 회의명·일시를 넣고, 라우팅 규칙으로 프로젝트를 정합니다.
3. [처리]를 누르면 로컬 전사(약 8분)와 Claude 요약이 진행되고, "검토 준비 완료" 알림이 옵니다.
4. 회의 상세에서 `미정` 담당자 1건을 지정하고, 이전 액션 1건을 "완료"로 확인한 뒤 [노션 발행]을 누릅니다.
5. 노션 회의록 DB에 페이지가 생기고 액션아이템 DB에 4건이 추가됩니다. `~/Documents/MeetingNotes/회의록앱/2026/09/`에 .md가 저장됩니다.

### 시나리오 B — 대면 회의를 아이폰으로 녹음

1. 아이폰 음성메모로 녹음하고 AirDrop으로 맥에 보냅니다(또는 iCloud 동기화 후 공유 → 감시 폴더).
2. 다운로드 폴더 감시가 파일을 감지하면 받은 녹음함에 카드가 생깁니다. 회의명을 입력하고 [처리]를 누릅니다.

### 시나리오 C — Alt로 녹음·전사까지 끝낸 경우

1. Alt에서 전사본을 내보내 지정 폴더에 저장합니다.
2. 앱은 **STT를 건너뛰고** 바로 요약합니다. 1분 안에 검토 대기 상태가 됩니다.

### 시나리오 D — LLM 키가 없는 동료

1. 설정 마법사에서 AI 키를 건너뜁니다. 로컬 전사까지만 자동으로 진행됩니다.
2. 회의 상세에서 [프롬프트 복사]를 누르고 사내에서 허용된 AI 채팅에 붙여넣습니다. 결과를 [결과 붙여넣기]로 넣고 발행합니다.

### 시나리오 E — 발행 후 수정

1. 팀장이 "A2 담당은 이영희"라고 피드백합니다.
2. 앱에서 수정하고 [노션 업데이트]를 누르면 같은 페이지와 같은 액션 행이 갱신됩니다. 노션에서 누군가 "진행 중"으로 바꾼 A1의 상태는 유지됩니다.
