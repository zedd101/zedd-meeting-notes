## 1. 개요

### 1.1 한 줄 정의

> 회의 녹음 파일을 넣으면, **회사 양식에 맞춘 회의록**을 만들어 **노션에 읽기 좋게 발행**하고 **같은 내용을 로컬 마크다운으로 보관**하는 데스크탑 앱.

### 1.2 문제

- 회의는 녹음하지만, 녹음을 듣고 정리해 공유하기까지 **회의 1건당 30~60분**이 듭니다. 그래서 공유가 늦어지거나 아예 빠집니다.
- 작성자마다 형식이 달라 **결정사항·할 일·담당자·기한이 흩어지고**, 지난 회의의 할 일이 어떻게 됐는지 추적하기 어렵습니다.
- 기존 AI 회의록 서비스의 한계:
  - 클라우드 전송이 필요하거나 유료 플랜을 요구합니다(노션 AI 회의 노트는 Business 플랜).
  - 회사 양식을 반영하기 어렵습니다.
  - 녹음 도구가 하나로 고정됩니다.

### 1.3 해결 방식

1. 사람들이 이미 쓰는 녹음 도구의 파일을 **자동 감지**합니다. Alt, Zoom, 음성메모, 윈도우 녹음기 등입니다.
2. **로컬(기본) 또는 클라우드 음성인식**으로 전사합니다.
3. **사용자 본인의 LLM API 키**로 회사 양식에 맞춰 요약합니다.
4. 노션의 **회의록 DB와 액션아이템 DB**에 가독성 높은 페이지로 발행합니다. 같은 구조의 **마크다운 파일**을 지정 폴더에 저장합니다.
5. 다음 회의에서 **이전 액션아이템을 자동 점검**해 회의 간 연속성을 만듭니다.

### 1.4 차별점

| | 이 앱 | 노션 AI 회의 노트 | Alt / Otter / Granola |
|---|---|---|---|
| 회사 양식 반영 | ✅ 업로드·붙여넣기·직접 작성 | ❌ | 제한적 |
| 녹음 도구 | 무엇이든 (폴더 감시) | 노션 안에서만 | 자체 앱 |
| 로컬 처리 | ✅ STT 로컬 기본 | ❌ | Alt만 ✅ |
| 노션 무료 플랜 | ✅ | ❌ (Business) | 연동 없음·유료 |
| 로컬 마크다운 보관 | ✅ | ❌ | 내보내기 |
| 액션아이템 DB + 회의 간 이월 | ✅ | 부분 | ❌ |

## 2. 목표 · 비목표 · 성공 지표

### 2.1 목표 (v1)

1. 녹음이 끝나고 **10분 안에** 검토 가능한 회의록이 준비되고, 확인 한 번으로 노션 발행과 로컬 저장이 끝납니다.
2. 결정사항·실행 항목(담당자·기한)·병목이 **누구나 첫 화면에서 파악**되는 노션 페이지를 만듭니다.
3. 레포를 받은 동료가 **15분 안에** 설치부터 첫 발행까지 마칠 수 있습니다.

### 2.2 비목표 (v1에서 하지 않음)

- 실시간(회의 중) 전사·자막
- 앱 자체 녹음 → **v1.5**
- 캘린더 연동, 참석자 자동 초대 → v2
- 다중 사용자 서버, 팀 공유 설정 동기화
- 노션 외 발행처(Confluence, Slack 등) → v2 이후 검토
- 모바일 앱 (아이폰 녹음은 iCloud·AirDrop으로 받음)

### 2.3 성공 지표

측정 기준은 **실제 회의 10건으로 만든 골든셋**입니다. 사람이 결정·액션을 직접 라벨링합니다. 통계는 회의 내용 없이 로컬에만 기록합니다.

| 지표 | 목표 |
|---|---|
| 60분 회의: 녹음 종료 → 노션 발행 (p50), 로컬 STT·M 시리즈 맥 | **≤ 10분** |
| 같은 조건, 클라우드 STT (p50) | ≤ 5분 |
| 사용자 검토 시간 중앙값 | ≤ 5분 |
| 수정량 10% 미만으로 발행된 회의록 비율 | ≥ 70% |
| 액션아이템 재현율 (골든셋 대비) | ≥ 90% |
| 액션아이템 정밀도 | ≥ 85% |
| 담당자·기한 정확도 | ≥ 80% |
| 수동 재시도 없이 파이프라인 성공 | ≥ 95% |
| 동료 설치: 다운로드 → 첫 노션 발행 | ≤ 15분 |
| 1시간 회의 클라우드 사용 시 총비용 (STT + LLM) | ≤ $0.30 |
| 4주 개인 사용 기간 중 본인 회의 처리율 | ≥ 80% |
| STT 글자 오류율(CER) | 제공자별로 기록 (로컬 vs Soniox) |

## 4. 핵심 워크플로우

```
 ① 수집            ② 전사              ③ 요약                ④ 검토        ⑤ 발행
┌────────┐     ┌──────────┐      ┌──────────────┐     ┌───────┐    ┌──────────────┐
│폴더 감시 │ ─▶ │ ffmpeg 변환│ ─▶ │ 템플릿 + 전사본│ ─▶ │검토·편집│ ─▶│노션 DB 페이지 │
│드래그앤드롭│    │ STT(로컬/  │      │ + 메타데이터   │     │(사람)  │    │로컬 .md 저장  │
│전사 텍스트 │    │  클라우드)  │      │ + 이전 액션    │     └───────┘    │원본 보관(선택) │
└────────┘     └──────────┘      │ → LLM 구조화 출력│                  └──────────────┘
      │  전사 텍스트면 ②를 건너뜀   └──────────────┘
```

### ① 수집

- **폴더 감시**: 소스별 프리셋과 사용자 폴더를 감시합니다([녹음 소스 리서치](research/recording-sources.md)).
  - 파일 크기가 일정 시간 변하지 않을 때까지 기다립니다(쓰는 중인 파일 제외).
  - 내용 해시로 **중복 처리를 막습니다.**
  - 임시 파일, iCloud 플레이스홀더, Zoom `.zoom` 변환 전 파일은 무시하고 안내합니다.
- **수동 입력**: 드래그앤드롭 또는 "파일 선택".
- **입력 종류**:
  - 오디오·영상 (`m4a mp3 wav aac flac ogg opus mp4 mov webm mkv`)
  - **전사 텍스트** (`txt md srt vtt`): Alt 등이 만든 전사본은 STT 없이 바로 요약합니다.
- **처리 모드**: 소스별로 `자동 처리` 또는 `확인 후 처리`(기본)를 고릅니다. 확인 후 처리면 받은 녹음함에 카드가 생깁니다.
- **메타데이터 추론**:
  - Zoom 폴더명(날짜·시각·회의 주제), 음성메모 DB(제목), 파일 생성 시각에서 **회의명·일시**를 추정합니다.
  - 라우팅 규칙(예: 회의명에 "주간 기획"이 있으면 → 프로젝트 A)으로 **프로젝트**를 지정하고, 프로젝트의 **기본 참석자**를 제안합니다.

### ② 전사

- ffmpeg로 16kHz 모노 WAV로 바꾼 뒤 STT 제공자로 전사합니다. 중간 WAV는 성공 후 삭제합니다.
- 결과는 구간 목록입니다: `segments[{id, start, end, speaker?, text}]`.
- **화자 구분**:
  - 제공자가 화자를 주면(Soniox 등) **화자 이름 매핑 UI**를 보여줍니다(화자1 → 홍길동).
  - 로컬 whisper처럼 화자 정보가 없으면 "화자 구분 없음"으로 표시합니다. LLM은 명시적 호명으로만 발언자를 추정합니다.
- **용어집**(사람 이름·제품명·사내 약어)을 STT 힌트로 넘깁니다.

### ③ 요약

- **입력**:
  - 템플릿 섹션 스펙
  - 전사본 (구간 ID 포함)
  - 메타데이터: 회의명, **회의 일자**, 참석자, 프로젝트
  - 용어집
  - **같은 프로젝트의 미완료 액션아이템** (노션 액션아이템 DB에서 조회)
- **출력**: `MeetingMinutes` 구조화 JSON
  - 섹션별 데이터
  - 결정·액션마다 **근거 구간 ID**
  - 이전 액션마다 `완료 / 진행 / 언급없음` 판단 제안
- **규칙**:
  - 상대 날짜는 회의 일자를 기준으로 절대 날짜로 바꿉니다.
  - 담당자·기한이 불명확하면 추측하지 않고 **`미정`** 으로 둡니다.
  - 자세한 규칙은 [기본 템플릿의 작성 규칙](templates/default-minutes.md#작성-규칙-llm-지시문에-포함)에 있습니다.
- **긴 회의**:
  - 기본은 한 번에 처리합니다. 1시간 회의는 약 2~4만 토큰이라 주요 클라우드 모델 컨텍스트에 충분히 들어갑니다.
  - 선택한 모델의 컨텍스트를 넘을 때만 구간을 나눠 요약하고 합칩니다. 이때도 근거 구간 ID는 유지합니다.
- **출력 검증**:
  - zod 스키마로 검증합니다. 실패하면 오류 내용을 붙여 **1회 복구 재시도**합니다.
  - 그래도 실패하면 원문을 `freeform`으로 살리고 사용자에게 알립니다.

### ④ 검토 (Human-in-the-loop)

- 회의 상세 화면에서 **구조화 데이터 자체를 편집**합니다.
  - 유형 섹션(결정·액션·리스크 등)은 폼과 표로, 자유 섹션은 마크다운 필드로 편집합니다.
  - 편집 결과는 노션과 마크다운 모두에 똑같이 반영됩니다.
- 결정과 액션을 클릭하면 **근거 구간으로 전사본이 스크롤**되고, 재생 위치도 그곳으로 옮겨갑니다(P1).
- `미정` 항목은 주황색으로 강조하고, 발행 전 체크리스트에 "미정 N건"을 보여줍니다.
- 이전 액션 판단 제안(완료·진행)을 확인하면 발행할 때 노션 상태에 반영됩니다.
- 설정에서 **자동 발행**을 켜면 검토 단계를 건너뜁니다(P2, 신뢰가 쌓인 뒤).

### ⑤ 발행

- **노션**
  - 회의록 DB에 페이지를 만들거나 **기존 페이지를 업데이트**합니다.
  - 액션아이템 DB에 행을 upsert하고, 녹취록은 하위 페이지로 둡니다.
  - 상세 규칙은 [노션 레이아웃 가이드](templates/notion-layout.md)에 있습니다.
- **로컬**: 마크다운 파일(+ 선택: 전사본 파일)을 저장합니다. frontmatter에 노션 URL을 기록합니다.
- **원본 보관**(선택): 로컬 보관 폴더나 Google Drive 동기화 폴더로 녹음 원본을 복사합니다.
- 완료되면 OS 알림을 띄웁니다. 알림을 누르면 노션 페이지가 열립니다.

## 5. 기능 요구사항

우선순위: **P0** = v1 필수 · **P1** = v1 목표(일정에 따라 v1.x) · **P2** = 이후

### F1. 녹음 소스 관리 — P0

- 프리셋 소스:
  - Zoom 로컬 녹화
  - 맥 음성메모: "공유 → 감시 폴더" 방식이 기본이고, 전체 디스크 접근 모드는 고급 옵션
  - 윈도우 녹음기
  - 다운로드 폴더 (AirDrop)
  - Alt 내보내기 폴더
- 사용자 지정 폴더를 여러 개 추가할 수 있습니다. 소스마다 켜기/끄기, 처리 모드, 기본 프로젝트를 정합니다.
- 소스 상태를 표시합니다(감시 중 / 권한 필요 / 폴더 없음).
- **음성메모 원본은 절대 이동·이름 변경하지 않습니다**(복사 전용).
- 받아들이는 사람을 위한 추천 녹음 도구 안내: [녹음 소스 리서치 5절](research/recording-sources.md#5-무료-녹음-서비스-추천-사용자-안내용).

### F2. 음성인식 (STT) — P0

- **로컬(기본)**: whisper.cpp `large-v3-turbo`
  - 첫 실행 때 모델을 다운로드합니다. 크기를 안내하고 이어받기를 지원하며, 양자화 모델을 기본으로 합니다.
  - 모델을 고를 수 있습니다.
- **클라우드**: v1은 **Soniox**(한국어 정확도·화자 구분)와 **Groq**(무료 티어)를 지원합니다. 나머지는 공통 인터페이스로 이후에 추가합니다.
- 설정 화면에 "정확도·화자 구분이 필요하면 Soniox 권장" 안내와 제공자별 예상 비용을 보여줍니다.
- 언어는 한국어가 기본이고, 영어가 섞인 회의를 허용합니다(자동 감지 옵션).
- 비교 근거: [STT 리서치](research/stt-options.md).

### F3. AI 제공자 관리 — P0

- **프리셋**:
  - Anthropic (Claude)
  - OpenAI (GPT)
  - Google Gemini
  - OpenRouter
  - 로컬 LLM (Ollama / LM Studio, OpenAI 호환 주소)
- **커스텀 추가**: 이름, OpenAI 호환 base URL, 키, 모델명을 입력해 목록에 없는 제공자를 추가합니다.
- 제공자마다 키 입력, **연결 테스트**, 모델 선택(기본 모델 추천), 켜기/끄기를 둡니다.
- **기본값 규칙**:
  - 키가 있는 제공자가 **하나면 자동으로** 그걸 씁니다.
  - **여러 개면 "기본값" 라디오 버튼**으로 하나를 고릅니다.
  - 회의 상세 화면에서 이번 회의만 다른 제공자로 다시 생성할 수 있습니다.
- 키는 **OS 키체인(Electron `safeStorage`)에만** 저장하고 renderer로 넘기지 않습니다. 화면에는 `sk-…abcd`처럼 가려서 보여줍니다.
- 템플릿 분석(F4)과 회의록 생성(③)은 같은 기본 제공자를 씁니다.

### F4. 템플릿 — P0

- **기본 템플릿**: [default-minutes.md](templates/default-minutes.md). 컨설팅 펌과 국내 대기업 관행을 합친 양식입니다.
- **사용자 템플릿 입력 세 경로** (탭으로 전환):
  1. **파일 업로드**: v1은 `.md` `.txt`, **P1**은 `.docx` `.pdf`.
  2. **텍스트 붙여넣기**: 회사 양식, 실제 회의록 예시, 또는 외부 LLM이 만든 템플릿 결과.
  3. **직접 작성**: 섹션 추가 버튼과 [템플릿 형식](templates/external-llm-prompt.md#1-앱-템플릿-형식-template-spec) 에디터.
- **분기**:
  - LLM 키가 있으면 "AI로 분석" 버튼 → 앱이 섹션 스펙을 자동으로 만듭니다.
  - 키가 없으면 앱이 템플릿 형식으로 직접 해석합니다. `{type=…}` 표기를 우선 쓰고, 없으면 제목으로 유형을 추정합니다.
- **도움말**: 입력창 아래 작은 글씨로 넣습니다.
  - "ChatGPT·Claude 같은 외부 AI에 회사 양식을 넣고 아래 프롬프트로 물어본 뒤, 결과를 여기에 붙여넣어도 됩니다."
  - **[프롬프트 복사]** 버튼과 [외부 LLM 프롬프트](templates/external-llm-prompt.md#2-외부-llm에-붙여넣을-프롬프트) 전문 보기를 둡니다.
- **미리보기**: 섹션 목록과 노션에서 보일 모습(샘플 데이터)을 보여줍니다. 섹션 순서를 드래그로 바꾸고 지시문을 편집할 수 있습니다.
- 템플릿은 **버전을 관리**하고, 각 회의에 `templateId@version`을 기록해 나중에 다시 렌더링할 수 있게 합니다.
- 프로젝트마다 기본 템플릿을 지정합니다.

### F5. LLM 키 없는 모드 — P1

- 회의 상세에서 **[프롬프트 복사]** 를 누르면 템플릿, 전사본, 메타데이터, 출력 형식 지시가 한 번에 복사됩니다.
- 외부 LLM 결과를 **[결과 붙여넣기]** 하면 해석한 뒤 검토·발행 흐름으로 이어집니다.
- 외부 서비스로 회의 내용이 전송된다는 경고를 보여줍니다.

### F6. 노션 발행 — P0

- **연결 마법사**:
  1. 내부 통합을 만드는 방법을 스크린샷으로 안내합니다.
  2. 토큰을 입력받습니다.
  3. "회의록" 부모 페이지를 통합에 공유하는 방법을 안내합니다.
  4. 연결을 확인합니다.
- **자동 구성**: 부모 페이지 아래에 **회의록 DB**, **액션아이템 DB**(relation), 사용 안내 페이지를 만듭니다. DB·데이터 소스·속성 ID를 저장합니다.
- **기본 뷰 자동 생성** — P1: 최근순 표, 프로젝트별 보드, 캘린더, 담당자별 액션 보드, 기한 임박. 실패하면 수동 가이드를 보여줍니다.
- **페이지 생성**: [노션 레이아웃 가이드](templates/notion-layout.md) 매핑을 따릅니다. 참석자가 노션 멤버와 매핑돼 있으면 @멘션, 기한은 날짜 멘션으로 넣습니다.
- **재발행 = 업데이트**:
  - `notionPageId`로 같은 페이지의 속성과 본문을 교체합니다.
  - 액션아이템은 `actionItemId`로 upsert합니다.
  - 노션에서 바뀐 **상태 값은 덮어쓰지 않고**, 앱에서 지운 액션은 보관(trash) 처리합니다.
  - 마지막 발행 뒤 노션에서 수정됐으면 경고합니다.
- **API 제약 처리**: 100블록 단위 분할, 중첩 2단계 초과분은 후속 append, 2,000자 분할, 초당 3회 제한 큐, 429 재시도.
- **시작 시 스키마 점검**: 누군가 속성 이름을 바꾸거나 지웠으면 복구 안내를 합니다.

### F7. 로컬 마크다운 저장 — P0

- **기본 경로**: `<문서>/MeetingNotes/<프로젝트>/YYYY/MM/YYYY-MM-DD_회의명.md` (맥·윈도우 공통)
- 설정에서 **[폴더 선택]** 버튼으로 전역 경로를 바꿀 수 있고, **프로젝트마다 저장 폴더**를 따로 지정할 수 있습니다(예: 각 프로젝트 레포의 `docs/meetings`).
- **내용**: 노션 페이지와 같은 구조입니다. GFM 표, `> [!NOTE]` 알림 문법, YAML frontmatter(일시·참석자·프로젝트·태그·상태·노션 URL·템플릿 버전)가 들어갑니다.
- **옵션**: 전사본을 별도 파일(`…_transcript.md`)로 저장합니다.
- 같은 이름의 파일이 있으면 `_2`를 붙입니다. 재발행하면 같은 파일을 덮어씁니다(앱 ID로 식별).

### F8. 원본 녹음 보관 — P1

- 옵션: 보관 안 함(기본) / 로컬 보관 폴더로 복사 / **Google Drive 동기화 폴더로 복사**.
- Google Drive for desktop 폴더를 자동 탐지합니다. 설치되어 있지 않으면 설치 가이드(무료 15GB)를 보여줍니다. API 연동이 아니라 폴더 복사 방식이라 OAuth가 필요 없습니다.
- 회의록 부록과 노션 "원본" 속성에 보관 위치를 기록합니다.

### F9. 초기 설정 마법사 — P0

1. **환영 및 고지**: 녹음 관련 법적 안내와 데이터 흐름 설명 (§8.1)
2. **녹음 도구 탐지**
   - 설치된 앱(Alt, Zoom)과 폴더(Zoom 녹화, 윈도우 녹음기, 다운로드, Google Drive)를 스캔합니다.
   - 발견한 소스를 체크박스 목록으로 보여줍니다.
   - Alt가 있으면 내보내기 폴더를 지정하는 방법을 안내합니다.
3. **권한 안내**: 필요한 경우에만 폴더 접근과 전체 디스크 접근을 안내하고, 시스템 설정으로 바로 가는 링크를 줍니다.
4. **음성인식 선택**: 로컬 모델 다운로드 또는 클라우드 키 입력
5. **AI 제공자 키** (건너뛰기 가능 → 키 없는 모드)
6. **노션 연결** (건너뛰기 가능 → 로컬 저장만)
7. **저장 폴더**: 기본값 확인 또는 변경
8. **테스트 실행**: 번들 한국어 샘플 클립(30~60초)으로 전체 파이프라인을 돌립니다. 노션에는 "테스트" 페이지로 발행한 뒤 삭제합니다.

- **P2 — Claude Code 셋업 지원**: 레포에 `CLAUDE.md`와 셋업 스킬을 둡니다. 레포를 받은 사람이 Claude Code에 권한을 주면, Claude가 그 PC의 녹음 도구·폴더를 탐색해 앱 설정 파일(`config.json`)을 채워줍니다.

## 6. 노션 페이지 디자인 가이드 (요약)

상세 매핑표와 예시는 [notion-layout.md](templates/notion-layout.md)에 있습니다.

**페이지 순서** (결론 → 할 일 → 문제 → 과정 → 근거)

1. 상단 속성: 일시, 프로젝트, 참석자, 상태, 결정 수, 액션 수
2. 목차
3. 💡 **핵심 요약**: 파란 콜아웃, 결론 한 문장 + 핵심 3개
4. ✅ **결정사항**: 초록 콜아웃(건수) + 표(결정, 결정권자, 근거, 구간)
5. **실행 항목**: 표(담당자 @멘션, 기한 날짜 멘션, 상태) + 액션아이템 DB 링크. `⚠️ 미정`은 주황색
6. 🔴 **이슈·리스크·병목**: 병목은 빨간 콜아웃, 나머지는 표
7. **안건별 논의**: 토글 헤딩(접힘)
8. **미결 사항**: 체크박스
9. **이전 액션 점검**: 표 (✅ 완료 / 🔄 진행 / ➖ 언급없음)
10. 📅 **차기 회의**: 콜아웃
11. **부록**: 녹취록 하위 페이지, 원본 링크, AI 작성 고지(회색)

**원칙**
- 색은 의미로만 씁니다: 파랑=요약, 초록=결정, 빨강=병목, 주황=주의, 회색=참고.
- 콜아웃은 페이지당 최대 4개입니다.
- 계획이나 구조는 필요할 때만 mermaid 코드 블록이나 컬럼 배치로 보여줍니다.
- 노션과 마크다운은 같은 DocAST에서 만들어지므로 구조가 항상 같습니다.

## 8. 비기능 요구사항

### 8.1 개인정보 · 보안 · 법적 고지

- **녹음 고지** (첫 실행 + 설정):
  - 통신비밀보호법상 **대화 참여자의 녹음은 적법**하지만, **대화에 참여하지 않은 제3자의 녹음은 불법**입니다.
  - 참석자에게 녹음 사실을 알리도록 권장하고, 회의록 부록에 "녹음 고지" 문구를 넣는 옵션을 둡니다.
  - 음성권 관련 법 개정 논의는 **확인 필요**로 둡니다.
- **국외 이전 고지**: 클라우드 STT·LLM을 쓰면 회의 음성과 텍스트가 해외 서버로 전송될 수 있습니다(개인정보보호법상 국외 이전). 회사 보안 정책을 확인하라고 안내합니다.
- **로컬 전용 모드 스위치**: 켜면 클라우드 STT·LLM 호출이 코드 수준에서 차단됩니다. 로컬 LLM만 허용하고, 노션 발행은 별도 스위치로 둡니다.
- **데이터 흐름 표** (설정 화면과 README에 표시):

  | 데이터 | 로컬 전용 모드 | 기본 (로컬 STT + 클라우드 LLM) | 클라우드 STT 사용 |
  |---|---|---|---|
  | 녹음 음성 | PC 밖으로 안 나감 | PC 밖으로 안 나감 | STT 제공자 |
  | 전사 텍스트 | 로컬 LLM만 | 선택한 LLM 제공자 | STT 제공자 + LLM 제공자 |
  | 회의록 | 로컬 (+노션 켜면 노션) | 로컬 + 노션 | 로컬 + 노션 |
  | API 키 | OS 키체인 | OS 키체인 | OS 키체인 |

- **키 보관**: `safeStorage`로 암호화하고 main 프로세스에서만 복호화합니다.
- **로그**: ID와 단계, 오류 코드만 남깁니다. 전사 내용과 회의록 내용은 기록하지 않습니다.
- **보관·삭제**: 중간 WAV는 자동 삭제합니다. 앱 내부 전사본과 오디오 사본의 보관 기간을 설정할 수 있습니다(기본 무기한, 예: 90일). 회의를 삭제할 수 있습니다.

### 8.2 성능

- 60분 회의 로컬 전사: M 시리즈 맥에서 10분 이하가 목표입니다(양자화 turbo 모델 기준, M1에서 실측).
- STT는 `utilityProcess`에서 실행해 UI가 멈추지 않게 합니다. 동시에 전사하는 작업은 1개입니다(큐).
- 노션 발행: 일반 회의록 기준 30초 이하.

### 8.3 안정성

- 단계별 상태를 저장하고 재시도합니다. 앱을 재시작해도 큐를 복구합니다.
- 오류 목록과 사용자 메시지, 복구 액션은 [architecture.md 오류 표](architecture.md#7-오류-처리)에 있습니다.

### 8.4 사용성 · 접근성

- UI는 **한국어가 기본**입니다. 문자열은 i18n 키로 관리해 영어 대비만 해둡니다.
- 시스템 다크 모드를 따르고, 키보드로 조작할 수 있으며, 스크린리더 라벨을 넣습니다(shadcn/Radix 기반).
- 빈 상태, 로딩, 오류 상태를 모든 화면에 정의합니다([UX 흐름](ux-flows.md)).

### 8.5 호환성

- macOS 13+ (Apple Silicon 우선, Intel x64 빌드 제공), Windows 10/11 x64.

## 9. 기술 아키텍처 (요약)

상세는 [architecture.md](architecture.md)에 있습니다.

- **Electron + electron-vite + React + TypeScript + Tailwind v4 + shadcn/ui**
  - Next.js를 쓰지 않는 이유는 [데스크탑 스택 리서치](research/desktop-stack.md#1-결론-nextjs-대신-electron--electron-vite--react)에 있습니다.
- **main 프로세스**: 소스 감시, 파이프라인, STT(utilityProcess), LLM(Vercel AI SDK), 노션, 파일 저장, 비밀 보관
- **preload**: 타입이 있는 IPC 브리지
- **renderer**: UI만
- **데이터 흐름**: `MeetingMinutes(JSON) → DocAST → 노션 블록 / 마크다운`
- **저장**: 앱 내부 데이터는 `userData/meetings/<id>/`(meeting.json, transcript.json), 결과물은 사용자 폴더(.md)

## 10. 배포 · 업데이트

  - 업데이트:
    - 맥은 **인앱 새 버전 알림**만 합니다(GitHub Releases API).
    - 윈도우는 electron-updater 자동 업데이트를 씁니다.

  - Apple Developer Program($99/년), Developer ID 서명과 공증을 CI에서 처리

  - 윈도우 서명: SignPath(오픈소스일 때) 또는 Certum

## 11. 로드맵

"걸어다니는 뼈대" 방식입니다. 가장 불확실한 **요약 품질**을 먼저 검증합니다.

| 단계 | 범위 | 완료 기준 |
|---|---|---|
| **M0** (현재) | 기획 문서, 리서치, 기본 템플릿 | 이 문서 승인 |
| **M1** | 스캐폴드(electron-vite + React + shadcn), **패키징 스파이크**, GitHub Actions 릴리스 | 3개 빌드 모두 설치·실행, 샘플 전사 성공 |
| **M2** | **전사 텍스트 입력**(Alt txt/srt/vtt) → LLM(프리셋 5종 + 커스텀, 기본값 규칙) → 검토 화면 → **마크다운 저장** | 골든셋 5건으로 액션 재현율 측정 |
| **M3** | STT: 로컬 whisper + Soniox + Groq, 화자 매핑, 용어집 | 골든셋 CER 측정, 60분 ≤ 10분 |
| **M4** | **노션 발행**: DB 자동 구성, 레이아웃, 재발행 업데이트, **액션 이월** | 노션 페이지가 레이아웃 가이드와 일치 |
| **M5** | 폴더 감시 + 소스 프리셋, **설정 마법사**, 처리 큐·알림, 히스토리·검색 | 동료 설치 → 첫 발행 ≤ 15분 |
| **M6** | 템플릿 업로드(docx/pdf), 키 없는 모드, 뷰 자동 생성, Google Drive 보관, 프로젝트·사람 디렉토리 | v1.0 릴리스 |
| **v1.5** | 앱 자체 녹음 (마이크 + 시스템 소리, 2트랙) | 맥 14.2+ / 윈도우에서 녹음 → 발행 |
| **v2** | 코드 서명·자동 업데이트, 캘린더 연동, 로컬 화자 구분(sherpa-onnx), Claude Code 셋업 스킬, 음성메모 내장 전사본 활용, 판매(라이선스 키) | – |

**M1 패키징 스파이크에서 결정할 것**
- whisper.cpp를 CLI 바이너리로 번들할지, Node 바인딩(`@fugood/whisper.node`)을 쓸지
- `asarUnpack` 설정, 아키텍처별 러너
- ffmpeg-static 라이선스(GPL) 확인

## 12. 리스크와 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 로컬 Whisper 한국어 정확도(CER 약 10~11%)와 화자 구분 부재 | 회의록 품질 저하 | Soniox 옵션과 안내, 용어집, 근거 링크로 검토를 쉽게, v1.5 2트랙 녹음, P2 로컬 화자 구분 |
| LLM이 담당자·기한을 지어냄 | 신뢰 하락 | `미정` 규칙, 근거 구간 필수, 검토 화면의 미정 체크리스트, 골든셋 정밀도 측정 |
| 맥 미서명 설치 마찰, 업데이트마다 권한 초기화 | 설치·재사용 이탈 | 전체 디스크 접근이 필요 없는 흐름을 기본으로, README 가이드, 판매 시 서명 전환 |
| Alt 저장 경로·포맷 비공개 | 자동 감지 불가 | 내보내기 폴더 방식, 탐지 스크립트, 전사 텍스트 입력 지원 |
| 음성메모 폴더 권한과 DB 손상 위험 | 데이터 손실 | 복사 전용, "공유 → 감시 폴더"를 기본 |
| 노션 API 제한(100블록, 2단계 중첩, 초당 3회)과 스키마 변경 | 발행 실패 | 분할 전송·큐·재시도, 시작 시 스키마 점검 |
| 네이티브 모듈 패키징(whisper, ffmpeg) | 릴리스 실패 | M1 스파이크, `utilityProcess`, 아키텍처별 빌드 |
| 제공자별 구조화 출력 차이(작은 로컬 모델의 JSON 깨짐 등) | 요약 실패 | JSON 모드 + zod 검증 + 복구 재시도 + freeform 대체 |
| API 비용 폭주 | 사용 중단 | 처리 전 예상 비용, 월 누적 표시 |
| 회사 보안 정책 위반 가능성 | 사용 불가 | 로컬 전용 모드, 데이터 흐름 표, 국외 이전 고지 |

## 13. 오픈 이슈

1. 회사 보안 정책상 클라우드 STT·LLM을 쓸 수 있는가? 로컬 전용 모드만으로 충분한가?
2. 팀 노션 워크스페이스의 플랜(무료 / Plus / Business)은? 파일 업로드 한도와 요청 한도가 달라집니다.
3. 화자 자동 이름 추정을 어디까지 할 것인가? 호명 기반 추정의 정확도는 골든셋으로 판단합니다.
4. Alt의 내보내기 형식(txt/md/srt 등)과 화자 정보 포함 여부 → Alt 설치 PC에서 확인이 필요합니다.
5. 제품명 확정과 `appId`(예: `io.zedd.meetingnotes`) → M1 전에 확정합니다.
6. **백엔드 없는 판매 방식**: 라이선스 키 API(Lemon Squeezy / Gumroad)를 클라이언트에서 확인하는 방식이 가능한가? 오픈소스로 할지 여부도 정해야 합니다(윈도우 무료 서명인 SignPath 조건과 연결).
7. 미서명에서 서명으로 전환할 때 사용자 권한과 키체인 항목을 어떻게 이전할 것인가?
8. 기본 LLM 모델 추천값: 제공자별 가격과 한국어 품질을 M2 골든셋으로 비교해 정합니다.
